# EnglishMaster 설계 문서

- 작성일: 2026-10-02
- 상태: 확정. 섹션 1~3(화면, 학습 로직, AI 튜터)은 사용자 승인. 섹션 4(기술 구조, 배포)는 사용자가 "묻지 말고 진행"으로 위임해서 기본값으로 결정.

## 1. 목표와 사용자

스픽(말하기 연습)과 말해보카(단어 학습)를 한 앱에 합친 **개인용 영어 학습 웹앱**이다.

- 사용자: 1명. 갤럭시(안드로이드) + 크롬. 한국어 UI.
- 사용 방식: 크롬에서 "홈 화면에 추가"로 설치한 PWA를 매일 10~20분.
- 사용자가 직접 정한 것
  - 단어와 말하기 비중은 비슷하게
  - UI/UX는 스픽, 말해보카와 비슷하게. 이름, 로고, 캐릭터 같은 브랜드 요소는 자체 제작
  - AI는 OpenRouter API를 사용. OpenAI 모델까지 비교해서 비용 대비 품질이 가장 좋은 모델로 정함
  - 서버 없는 웹앱 (설계안 A)

### 성공 기준

1. 폰에서 앱을 열고 바로 단어 복습과 소리 내어 말하기 연습을 할 수 있다.
2. 말한 문장을 음성인식으로 채점받고, 어떤 단어를 놓쳤는지 볼 수 있다.
3. 진도, 복습 일정, XP, 연속 학습일이 앱을 껐다 켜도 유지된다.
4. OpenRouter를 연결하면 AI와 영어로 대화하면서 문장 교정을 받는다.
5. 인터넷이 없어도 단어 학습은 된다. 음성인식과 AI는 인터넷이 필요하다.

## 2. 범위

**제외 (나중에 고려)**

## 3. 화면과 흐름

### 탭 구조
하단 탭 5개: **홈 · 단어 · 말하기 · AI 튜터 · 나**. 학습 세션(단어 퀴즈, 레슨, AI 대화)은 탭 바 없이 전체 화면으로 열리고, 왼쪽 위 X 버튼이나 안드로이드 뒤로가기로 나간다.

### 첫 실행 (온보딩)
1. 환영 화면
2. 레벨 선택: 기초 / 일상 / 중급 / 고급
3. 하루 목표: 가볍게 30 XP / 보통 50 XP / 열심히 100 XP
4. 하루 새 단어 수: 5 / 10 / 15 / 20 (기본 10)
5. 완료 후 홈. AI 연결은 나중에 설정에서 한다.

### 홈
- 날짜, 인사말, 연속 학습일(불꽃 아이콘)
- 오늘 목표 진행률 (원형 링, XP)
- "오늘의 단어" 카드: 복습 N개 · 새 단어 M개 + [학습 시작]. 남은 게 없으면 "오늘 단어 완료" + [더 배우기]
- "이어서 말하기" 카드: 아직 완료하지 않은 첫 레슨과 그 코스의 진행률(예: 여행 2/6). 레슨 중간 진행 상태는 저장하지 않는다(레슨 하나가 5~10분이라서)
- "AI 튜터와 대화하기" 카드
- 이번 주 학습 여부 (월~일 점 7개)

### 단어 탭
- 레벨별 진행 요약 (새 단어 / 학습 중 / 마스터 개수)
- [학습 시작]
- 단어 목록: 레벨 필터, 상태 필터, 검색. 단어를 누르면 상세(뜻, 예문, 발음 듣기, 복습 단계)

### 단어 학습 세션 (말해보카 스타일)
- 상단: X 버튼, 진행 바, "7/15"
- 새 단어는 소개 카드(단어, 품사, 발음 듣기, 뜻, 예문)를 먼저 보여주고 퀴즈로 넘어간다
- 퀴즈 후 하단 시트: 맞으면 초록 "정답이에요", 틀리면 빨강 "아쉬워요" + 정답, 예문, 발음 듣기, [계속]
- "모르겠어요" 버튼 = 오답 처리
- 결과 화면: 정답률, 얻은 XP, 연속 학습일, 다시 볼 단어 목록

### 말하기 탭
- 코스 4개 아래 레슨 6개씩 카드 목록. 레슨마다 완료 여부와 최고 점수 표시

### 말하기 레슨 (스픽 스타일 4단계 + AI)
1. **표현 익히기**: 표현 6개를 카드로. 영어 문장, 한국어 뜻, 팁, 자동 발음 재생
2. **따라 말하기**: 발음 듣기(보통/0.7배속) → 마이크 → 채점(80점 이상 통과). 맞은 단어 초록, 놓친 단어 빨강. 다시 하기 / 다음
3. **영어로 말하기**: 한국어 문장을 보고 영어로 말하기(70점 이상 통과). 결과에 모범 답안 표시
4. **대본 롤플레이**: 상대 대사는 발음 재생 + 화면 표시, 내 대사는 한국어 힌트(영어 보기 토글) → 말하기 → 채점(60점 이상 통과)
5. **AI 롤플레이** (OpenRouter 연결 시): 같은 상황으로 AI와 자유롭게 대화
6. 완료 화면: 점수, XP

### AI 튜터 탭
- 미연결: 기능 소개 + [OpenRouter 연결] + [키 직접 입력]
- 연결됨: "자유 대화" 주제 10개, "상황 롤플레이" 24개(레슨 상황), 지난 대화 기록
- 대화 화면: AI 말풍선(다시 듣기, 번역 보기), 내 말풍선 + 교정 카드, 하단에 [힌트] [마이크] [입력], 상단에 [대화 끝내기]
- 대화 끝: 요약 화면(잘한 점, 고칠 점, 써먹을 표현, 이번 대화 비용)

### 나 탭
- 통계: 연속 학습일, 최장 연속, 총 XP, 외운 단어(마스터), 학습 중 단어, 완료 레슨
- 학습 달력 (최근 12주, 학습한 날 표시)
- 설정: 레벨, 하루 목표, 새 단어 수, 발음 속도, 목소리, AI 답변 자동 재생, AI 연결/해제, AI 모델, 백업 내보내기/가져오기, 전체 초기화

### 공통
- 모든 말하기 화면에 [직접 입력](키보드) 대안이 있다.
- 마이크 권한이 거부되거나 음성인식이 없는 브라우저면 안내 문구를 띄우고 키보드 입력으로 자동 전환한다.

### 디자인 방향
흰 배경, 보라 계열 포인트 색 하나, 큰 둥근 버튼과 카드, 상단 진행 바, 정답/오답 하단 시트, 큰 원형 마이크 버튼(듣는 중 파동 애니메이션), 세션 완료 시 축하 효과. 폰트는 Pretendard. 브레인스토밍에서 보여준 시안(홈, 단어 퀴즈, 따라 말하기, AI 튜터) 구성을 따른다.

## 4. 콘텐츠

### 단어 800개
| 레벨 | 이름 | 대상 | 개수 |
|---|---|---|---|
| 1 | 기초 | 중학 수준 필수 어휘 (A2) | 200 |
| 2 | 일상 | 일상 회화 어휘 (B1) | 200 |
| 3 | 중급 | 수능·토익 핵심 (B2) | 200 |
| 4 | 고급 | 비즈니스·고급 표현 (C1) | 200 |

필드: `id`(예: `l2-037`), `word`, `pos`(noun/verb/adjective/adverb/phrase 등), `meaning`(한국어, 쉼표로 구분된 1~3개 뜻), `example`(영어 예문), `exampleKo`(해석).

작성 규칙 (검증 테스트로 강제)
- 예문에 표제어가 **그대로**(대소문자 무시, 단어 경계 기준) 들어 있어야 한다. 빈칸 퀴즈에서 보기와 문법이 맞도록 하기 위해서다.
- 전체 800개 안에서 표제어 중복 금지, `id` 중복 금지.
- 뜻은 짧게(보기 버튼에 들어갈 길이), 예문은 일상에서 쓸 만한 문장.

### 말하기 레슨 24개
| 코스 | 레슨 |
|---|---|
| 일상 | 자기소개하기, 안부와 근황, 취미 이야기, 주말 계획, 음식과 취향, 길 묻고 답하기 |
| 여행 | 공항과 기내, 호텔 체크인, 식당에서 주문하기, 교통수단 이용하기, 쇼핑과 환불, 곤란한 상황 해결하기 |
| 직장 | 첫 인사와 스몰토크, 회의에서 의견 말하기, 일정 잡기, 전화와 화상회의, 부탁하고 거절하기, 진행 상황 보고하기 |
| 감정·관계 | 감사와 사과, 축하와 위로, 동의와 반대, 추천과 조언, 불만 말하기, 초대와 약속 |

레슨 필드
- `expressions`: 6개. `{ en, ko, tip? }`
- `dialogue`: `{ setting(한국어 상황 설명), aiRole, userRole, lines: [{ speaker: "ai" | "user", en, ko }] }`. 6~8줄, 상대(ai)가 먼저 말한다. 내 대사(user)에는 그 레슨의 핵심 표현이 최소 2개 들어간다.
- `aiScenario`: `{ role(AI가 맡을 역할, 영어), situation(상황, 영어), opening(AI 첫 대사) }`

### AI 자유 대화 주제 10개
오늘 하루, 취미, 여행, 음식, 영화와 드라마, 일과 공부, 주말 계획, 목표와 꿈, 고향, 최근 산 물건. 주제마다 AI 첫 대사를 미리 정해 둬서 대화 시작에는 API를 부르지 않는다.

## 5. 학습 로직

### 간격 반복 (Leitner 7단계)
- 단계별 다음 복습까지 간격: 1단계 1일, 2단계 2일, 3단계 4일, 4단계 7일, 5단계 15일, 6단계 30일, 7단계 60일
- 새 단어를 처음 맞히면 1단계(다음 날 복습).
- 맞히면 한 단계 올라간다. 7단계에서 맞히면 **마스터**가 되고 더는 일정에 잡히지 않는다.
- 틀리면 1단계로 내려가고(다음 날 복습), 같은 세션 마지막에 한 번 더 나온다. 이 재출제는 단계를 바꾸지 않는다(다시 틀려도 1단계 그대로).
- 날짜는 폰의 현지 자정 기준 `YYYY-MM-DD`.

### 세션 구성
- 한 세션 최대 15문제. 오늘 기한이 된 복습 단어(오래된 순)를 먼저, 남은 자리에 새 단어(오늘 남은 새 단어 한도까지).
- 새 단어는 현재 레벨에서 아직 안 배운 단어를 순서대로. 현재 레벨을 다 배우면 다음 레벨에서 이어서.
- 복습도 새 단어도 없으면 "오늘 단어 완료". [더 배우기]는 오늘 새 단어 한도를 무시하고 새 단어 10개 세션을 연다.

### 단계별 퀴즈 유형
| 단계 | 유형 후보 (무작위 하나) |
|---|---|
| 새 단어 | 뜻 고르기 |
| 1 | 뜻 고르기, 듣고 고르기 |
| 2 | 듣고 고르기, 단어 고르기 |
| 3 | 단어 고르기, 빈칸 채우기 |
| 4 | 빈칸 채우기, 말해서 맞히기 |
| 5~7 | 말해서 맞히기, 빈칸 채우기, 단어 고르기 |

- 뜻 고르기: 영어 단어 → 한국어 뜻 4지선다
- 듣고 고르기: 발음만 듣고 → 한국어 뜻 4지선다 (다시 듣기 가능)
- 단어 고르기: 한국어 뜻 → 영어 단어 4지선다
- 빈칸 채우기: 예문의 표제어 자리를 빈칸으로 → 영어 단어 4지선다 (해석 함께 표시)
- 말해서 맞히기: 한국어 뜻과 빈칸 예문 → 단어를 말한다. 음성인식 후보 중 하나라도 표제어를 포함하면 정답. 키보드 입력 가능.
- 오답 보기 3개: 같은 레벨에서 고르되 같은 품사를 우선, 뜻 문자열이 정답과 같은 것은 제외.

### 말하기 채점
1. 정규화: 소문자, 문장부호 제거, 공백 정리, 축약형 풀기(I'm→i am, don't→do not, can't→can not, won't→will not, 'll→will, 're→are, 've→have, 'd→would, let's→let us), 숫자 0~20은 영어 단어로, okay→ok.
2. 정답 문장 단어열과 인식 결과 단어열의 최장 공통 부분열(LCS)로 맞은 정답 단어를 표시.
3. 점수 = 맞은 정답 단어 수 / 정답 단어 수 × 100 (반올림). 인식 후보가 여러 개면 가장 높은 점수를 쓴다.
4. 통과 기준: 따라 말하기 80, 영어로 말하기 70, 대본 롤플레이 60.
5. 한계: 음소 단위 발음 평가가 아니라 "음성인식이 알아들었는가" 기준이다.

### XP와 연속 학습일
- 단어 정답 +2 (세션 끝 재출제 정답은 0), 말하기 문장 통과 +5, 레슨 완료 +20, AI 대화 한 턴 +3
- 하루 목표 30 / 50 / 100 XP
- 연속 학습일: 단어 세션 완료, 레슨 완료, AI 대화 종료(내 발화 1개 이상) 중 하나라도 한 날을 "학습한 날"로 기록. 오늘 또는 어제까지 끊김 없이 이어진 학습한 날 수가 현재 연속 학습일이다(오늘 아직 안 했어도 하루가 끝나기 전엔 끊기지 않음).

## 6. AI 튜터 (OpenRouter)

### 연결
- OAuth PKCE: `https://openrouter.ai/auth?callback_url=<앱 주소>&code_challenge=<S256>&code_challenge_method=S256` → 앱으로 돌아오면 `?code=` → `POST https://openrouter.ai/api/v1/auth/keys` `{ code, code_verifier, code_challenge_method }` → `{ key }`를 폰에 저장.
- `code_verifier`는 연결을 시작할 때 localStorage에 잠시 저장하고 교환 후 지운다(설치형 앱에서 외부 페이지를 오가도 유지되도록).
- 키 직접 붙여넣기도 지원. 연결 해제 시 키를 지운다.
- 설정 화면에 OpenRouter에서 키 사용 한도를 걸어두라는 안내를 넣는다.
- OpenRouter API는 CORS를 전부 허용한다(`Access-Control-Allow-Origin: *`, 2026-10-02 확인). 그래서 서버가 필요 없다.

### 모델
- 후보(모두 추론 최소 설정): `openai/gpt-6-luna`, `openai/gpt-5.6-luna`, `openai/gpt-5.4-mini`, `google/gemini-3.8-flash`, `google/gemini-3.5-flash-lite`, `anthropic/claude-haiku-4.5`. 품질 기준점으로 `anthropic/claude-sonnet-5.5`.
- 공개 자료(Artificial Analysis): GPT-6 Luna 추론 끔 상태 지능 지수 18, 첫 토큰 0.72초 / Gemini 3.8 Flash low 33, high 41, 초당 220~310 토큰 / Gemini 3.5 Flash-Lite 22, 첫 토큰 p50 1.52초. 추론을 켜면 첫 응답이 5~20초 이상이라 대화에 부적합하다.
- 확정 방법: `scripts/bench-models` 스크립트로 한국인이 자주 틀리는 문장 + 이미 맞는 문장을 후보 모델에 보내서 응답 시간(중앙값, p90), 턴당 비용, JSON 형식 성공률, 교정 정확도(틀린 문장을 고쳤는지, 맞는 문장을 건드리지 않았는지)를 비교한다. 결과로 기본 모델을 정한다.
- 키가 아직 없으므로 **임시 기본값은 `google/gemini-3.8-flash`(추론 최소)**. 저렴한 후보 중 지능 지수가 가장 높고 출력이 빠르기 때문이다. 벤치마크 후 바꾼다.
- 설정에서 후보 목록 중 선택하거나 OpenRouter 모델 ID를 직접 입력할 수 있다. 모델별 추론 파라미터는 앱 안의 모델 목록에 정의한다.

### 요청 형식
- `POST https://openrouter.ai/api/v1/chat/completions`
- 헤더: `Authorization: Bearer <key>`, `HTTP-Referer: <앱 주소>`, `X-Title: EnglishMaster`
- 본문: `model`, `messages`(system + 최근 16개 메시지 + 새 발화), `response_format: { type: "json_schema", json_schema: { name, strict: true, schema } }`, 모델별 `reasoning` 설정, `max_tokens: 600`, `usage: { include: true }`
- 타임아웃 25초.

### 한 턴 응답 (JSON)
```json
{
  "reply": "AI의 영어 답변 (1~3문장, 질문으로 대화를 이어감)",
  "replyKo": "답변의 한국어 해석",
  "correction": { "corrected": "고친 문장", "explanationKo": "한국어 설명 1~2문장" },
  "hints": ["다음에 할 수 있는 말 1", "다음에 할 수 있는 말 2"]
}
```
`correction`은 고칠 게 없으면 `null`. 대화 기록으로 다시 보낼 때는 AI 메시지의 `reply`만 보낸다(토큰 절약).

### 프롬프트 원칙
- 역할: 친근한 영어 튜터 겸 롤플레이 상대. 학습자 레벨(기초~고급)에 맞춘 어휘와 문장 길이.
- 답변은 짧게(1~3문장), 대화를 이어가는 질문으로 끝낸다. 롤플레이에서는 역할을 유지한다.
- 교정: 문법 오류, 틀린 단어, 확실히 어색한 표현만. 맞는 문장은 교정하지 않는다. 대소문자, 문장부호, 음성인식이 만든 것으로 보이는 오류는 무시한다.
- 학습자가 한국어로 말하면 영어로 어떻게 말하는지 `correction`으로 알려준다.
- 설명은 한국어, 1~2문장.

### 대화 요약
대화를 끝내면 대화 전체를 보내 JSON으로 받는다: `{ goodPoints: string[], fixes: [{ original, corrected, explanationKo }], usefulExpressions: [{ en, ko }] }`. 이번 대화에 든 비용(OpenRouter `usage.cost` 합계, 달러)을 원화 근사치(1달러 = 1,400원으로 계산)와 함께 표시한다.

### 오류 처리
| 상황 | 안내 |
|---|---|
| 401 | 연결이 만료됐어요. 다시 연결해 주세요 (+ 설정으로 이동) |
| 402 | OpenRouter 크레딧이 부족해요 |
| 429, 5xx | 1회 자동 재시도 후 "잠시 후 다시 시도해 주세요" |
| 네트워크 끊김, 타임아웃 | 인터넷 연결을 확인해 주세요 (+ 다시 보내기) |
| JSON 형식 오류 | 1회 자동 재시도 후 실패 안내 |

대화 내용은 OpenRouter와 모델 제공사로 전송된다는 점을 연결 화면에 표시한다.

## 7. 기술 구조

### 스택
- React 19 + TypeScript + Vite
- Tailwind CSS v4 (`@tailwindcss/vite`)
- Zustand (상태 + localStorage 저장)
- React Router (HashRouter: GitHub Pages에서 새로고침해도 404가 안 나게)
- vite-plugin-pwa (매니페스트, 서비스 워커, 오프라인 캐시)
- lucide-react 아이콘, Pretendard 폰트(jsDelivr CDN, 서비스 워커가 캐시)
- Vitest (단위 테스트)

### 폴더 구조
```
src/
  main.tsx, App.tsx              앱 진입점, 라우터
  index.css                      Tailwind + 디자인 토큰
  content/                       vocab-l1~l4.json, lessons.json, topics.json, index.ts(타입 + 로더)
  lib/                           순수 로직 (UI 없음, 단위 테스트 대상)
    date.ts                      로컬 날짜 키, 날짜 차이
    srs.ts                       Leitner 일정 계산
    session.ts                   단어 세션 구성, 퀴즈 유형 선택, 오답 보기 생성
    scoring.ts                   말하기 정규화, LCS 정렬, 점수
    progress.ts                  XP, 연속 학습일, 통계 계산
    random.ts                    시드 고정 가능한 난수 (테스트용)
    backup.ts                    백업 직렬화/검증
    ai/models.ts                 모델 목록과 모델별 파라미터
    ai/prompts.ts                시스템 프롬프트, JSON 스키마
    ai/openrouter.ts             요청, 응답 파싱, 오류 분류
    ai/oauth.ts                  PKCE
  speech/                        브라우저 API 래퍼
    tts.ts                       speechSynthesis (목소리 선택, 속도)
    useSpeechRecognition.ts      webkitSpeechRecognition 훅 (중간 결과, 후보 3개)
  store/                         Zustand 스토어 (settings, progress, tutor)
  components/                    공통 UI (Button, ProgressBar, BottomSheet, TabBar, MicButton, ...)
  screens/                       화면별 폴더 (onboarding, home, vocab, speaking, tutor, me)
scripts/bench-models.ts          OpenRouter 모델 비교 (node로 실행)
```

### 저장 데이터 (localStorage, 키 접두사 `em:`)
- `settings`: 레벨, 하루 목표, 새 단어 수, 발음 속도, 목소리 URI, AI 자동 재생, 온보딩 완료 여부
- `progress`: 단어별 `{ box, due, correct, wrong, mastered }`, 레슨별 `{ completedAt, bestScore }`, 날짜별 XP, 학습한 날 목록, 날짜별 새로 배운 단어 수
- `tutor`: API 키, 모델 ID, 대화 기록(최근 30개)
- 각 스토어에 `version`을 두고 형식이 바뀌면 마이그레이션한다.
- 처음 실행할 때 `navigator.storage.persist()`를 요청해 브라우저가 데이터를 지우지 않게 한다.
- 백업: 세 스토어를 하나의 JSON 파일(`englishmaster-backup-YYYY-MM-DD.json`)로 내보낸다. 가져올 때는 형식을 검증한 뒤 덮어쓴다. API 키는 백업에 넣지 않는다.

### 음성
- 음성인식: `webkitSpeechRecognition`, `lang = "en-US"`, `interimResults = true`, `maxAlternatives = 3`, `continuous = false`. 마이크를 누르면 시작하고, 다시 누르거나 말이 끝나면 종료.
- 발음 재생: `speechSynthesis`. en-US 목소리 중 Google 목소리를 우선 선택하고, 설정에서 바꿀 수 있다. 속도 0.7~1.2.
- 크롬 안드로이드 음성인식은 온라인으로 동작한다. 인터넷이 없으면 "직접 입력"으로 안내한다.

### PWA
- 이름 EnglishMaster, `display: standalone`, `orientation: portrait`, 보라색 테마, 아이콘 192/512 + maskable
- 서비스 워커: 앱 파일과 콘텐츠 JSON을 미리 캐시(오프라인 단어 학습). Pretendard 폰트는 런타임 캐시. 새 버전이 나오면 자동 갱신.

## 8. 배포

- GitHub 저장소 `BusanTree/englishmaster`, GitHub Actions로 GitHub Pages 배포(`main`에 push → 테스트 → 빌드 → 배포).
- 주소: `https://busantree.github.io/englishmaster/` (Vite `base: "/englishmaster/"`). OAuth `callback_url`도 이 주소.
- 비공개 저장소에서 Pages를 쓸 수 없는 요금제면 공개 저장소로 만든다. 코드에 비밀 정보는 없다(API 키는 폰에만 저장). 커밋 이메일은 GitHub noreply 주소.
- 폰에서 쓰는 법: 크롬으로 주소 열기 → 메뉴 → "홈 화면에 추가" → 설치된 앱에서 마이크 권한 허용 → 설정에서 OpenRouter 연결.

## 9. 테스트

- 단위 테스트(Vitest): `srs`, `session`(세션 구성, 퀴즈 유형, 오답 보기), `scoring`(정규화, LCS, 점수), `progress`(XP, 연속 학습일), `date`, `backup`, `ai/openrouter`(응답 파싱, 오류 분류), `ai/oauth`(PKCE challenge).
- 콘텐츠 검증 테스트: 단어 800개(레벨별 200), 필수 필드, 표제어와 id 중복 없음, 예문에 표제어 포함 / 레슨 24개, 표현 6개, 대본 6~8줄이고 ai로 시작, aiScenario 필수 필드.
- 수동 확인: 내장 브라우저를 모바일 크기(375×812)로 놓고 온보딩 → 단어 세션 → 레슨 → AI 화면(미연결 상태) → 설정 → 백업 흐름을 직접 눌러본다. 음성인식은 PC에서 확인하기 어려우므로 키보드 입력 경로로 채점 흐름을 확인한다.
- 실기기 확인(사용자): 갤럭시 크롬에서 설치, 마이크 채점, OpenRouter 연결.

## 10. 위험과 대응

| 위험 | 대응 |
|---|---|
| 크롬 음성인식이 가끔 못 알아듣거나 인터넷이 필요함 | 다시 하기, 직접 입력, 관대한 통과 기준(60~80) |
| 삼성 인터넷 브라우저는 음성인식 지원이 불확실 | 음성인식 미지원 감지 시 "크롬에서 열어주세요" 안내 |
| 브라우저 데이터 삭제로 진도 유실 | `storage.persist()` 요청, 백업 내보내기 |
| 모델이 JSON 형식을 어김 | `json_schema` strict, 1회 재시도, 실패 안내 |
| 모델 실측 전 기본값이 최적이 아닐 수 있음 | 임시 기본값 + 설정에서 변경, 키 받으면 벤치마크 후 확정 |
| 프로젝트가 OneDrive 폴더 안이라 node_modules가 동기화됨 | 동작에는 지장 없음. 사용자에게 알림 |
